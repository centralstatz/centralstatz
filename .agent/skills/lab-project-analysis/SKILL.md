# Lab project analysis

Read the source’s `AGENTS.md` first. Respect source-specific scope and privacy instructions.

For code sources, inspect README and project metadata, entry points, documentation, examples, tests, screenshots, release/deployment configuration, recent history when useful, license, contributors, disclaimers, and roadmap/issues available within scope. Do not infer maturity from code volume.

For a live site/app, inspect purpose, primary workflow, visible functions, intended users, documentation, disclaimers, and obvious limits. Do not reproduce protected content unnecessarily.

For research or concepts, inspect notes, papers, diagrams, examples, scaffolding, outputs, presentations, and discussions supplied by Alex.

Check all sources for credentials, PHI, private names, client data, internal URLs, local paths, confidential logic, sensitive screenshots, or unpublished collaborators. Mark rather than reproduce them.

Produce an evidence matrix with four sections:

- **Supported fact** — directly evidenced, with source location.
- **Reasonable inference** — likely but unstated; include rationale and confidence.
- **Unknown** — information needed before making a public claim.
- **Private or unsuitable for publication** — describe the category, not the sensitive value.

Answer:

1. What problem is being addressed and why does it matter?
2. What is distinct about the approach?
3. What tangible artifact exists? What does not?
4. What are the honest stage and status?
5. What are the central question and current hypothesis?
6. What works now, and what is unvalidated?
7. What are the key limitations and next meaningful step?
8. What external input would genuinely help?
9. What ownership/attribution language is required?
10. Is publication safe, and at what detail level?

Use the stage/status definitions in `../../../docs/lab-project-ingestion.md`. Never choose Pilot or Production without direct evidence. Hand the evidence matrix and interpretation to `../lab-project-content/SKILL.md`.
